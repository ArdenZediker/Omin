# 上下文优先级与召回排序 · 业界调研报告
> 主题：为 Omni 建立可回归、低成本的上下文优先级与超限处理策略。
> 定位：核验用户提供的工程文章，支持上下文管理的首期实现与后续评估。
> 日期：2026-11-27
> 状态：首期代码已实施；真实任务质量对照待积累样本。

## 0. 证据标注约定

- 带编号链接的内容为来源事实；`【分析】`为结合 Omni 代码作出的判断，不代表来源结论。
- CSDN 文章属于个人工程经验；OpenAI、Anthropic 文档用于交叉核验，不把建议性原则描述成固定算法。

## 1. 执行摘要

文章给出的核心排序可作为合理原则：安全约束最高，当前问题和任务状态高于旧记忆，无关闲聊优先淘汰。它还建议在当前任务摘要、最近原文与相关长期记忆之间做组合，而不是只保留固定最近 N 条或简单截断。[1]

**对 Omni 的建议：保留当前已有的模型无关剪枝与摘要路径，首期只补上相关性召回排序、近期对话保护、摘要字段要求和首轮 token 预算门；不引入新服务、向量召回或评分模型。** OpenAI 的上下文/压缩文档强调窗口预算以及压缩后状态连续性；Anthropic 的上下文工程经验强调保留决策与实施细节、压掉冗余信息。这些支持方向，但不能证明本项目的具体权重必然提升回答质量。[2][3][4]

## 2. Omni 现状与痛点

实现前检查到的代码现状：

- `src/chat/promptModules.ts` 将基础身份、人设、项目指令、历史召回、知识库协议、工具协议和技能按有界片段组装；召回提示限制长期记忆 8 条、摘要 5 条，且声明旧上下文与当前问题冲突时以当前输入为准。
- `src/chat/storage.ts` 的旧 `searchSessionSummaries` / `searchProjectMemories` 只做查询字符串包含匹配；没有完整短语/分词覆盖率排序，也没有新近程度排序。
- `src/hooks/useChatSessions.ts` 已按项目和 `memoryScope` 限定召回范围；摘要/记忆召回上限分别为 5 条。
- `src/chat/engine.ts` 使用约 75% 上下文窗口作为压缩预算，先剪枝历史工具结果，再摘要较早历史；此前首轮只在消息数大于 4 时检查预算，压缩保护 system/knowledge 以及最近一条 user 消息。
- 知识库块被作为独立 system 消息加入请求；提示词已明确知识库资料不是高优先级系统指令。

【分析】项目已有摘要、隔离范围和分级压缩，没必要整体替换。主要改进点是召回排序缺少相关性和时间信号，以及首轮预算判断依赖消息数量。压缩边界扩大也有成本风险：保护过多最近消息会让短对话没有可压缩内容，因此近期保护应自适应，并继续覆盖超长输入。

## 3. 业界方案分类对比

| 范式 | 依据 | 可借鉴点 | 不直接照搬的部分 |
|---|---|---|---|
| 指令权限层级 | OpenAI Model Spec 区分不同来源指令的权威；低权限消息不能覆盖高权限约束。[2] | 把“当前问题高于旧记忆”与“用户能覆盖系统安全”明确区分 | 不能仅靠 system 文本排序获得形式化权限保障 |
| 上下文预算/压缩 | OpenAI 对话状态与 compaction 文档说明上下文窗口有边界，压缩时要保留后续交互需要的状态。[3][4] | 超限前检查 token；压缩后保留继续任务所需上下文 | 不把特定产品 API 或固定裁剪参数移入 Omni |
| 结构化状态与高保真摘要 | Anthropic 工程文章主张在压缩时保留决策、架构与实现细节，减少冗余工具输出。[5] | 摘要明确区分目标、已确认事实/约束、决策、完成项、未决问题、下一步 | 其工程经验不是 Omni 任务集上的效果基准 |
| 固定 N 条/固定 token 权重 | 用户提供文章展示了上下文分层及示例配额。[1] | 用作初始思考框架 | 文章示例数字和演示 token 估算不直接复制 |

【分析】首期采用确定性本地词项排序并配合新鲜度轻微加权，避免外部嵌入调用、模型自评和新增持久状态；将来若样本显示词项召回明显漏召，再评估混合语义召回。

## 4. 深入标杆

1. **CSDN：《上下文管理：如何让 AI 记住用户之前说过的话》**。文章列出用户图中的优先级，并建议近期原文、任务摘要与相关长期记忆混合使用；同时提醒旧信息与无关闲聊应降低权重。[1] 文章本身属于二手工程经验，不把示例数量当作最佳参数。
2. **OpenAI Model Spec**。提供指令权限层级的定义，支撑“安全约束高于用户问题、用户问题高于普通历史记忆”的冲突处理边界。[2]
3. **OpenAI Conversation State / Compaction**。说明长交互需要管理上下文窗口，压缩后的状态要继续支持后续调用。[3][4]
4. **Anthropic Context Engineering**。说明如何在有限上下文中选择信息，并在压缩中保留关键决策、实施细节与待办。[5]

## 5. 对 Omni 的推荐方案

### 5.1 排序与冲突优先级

```text
系统与安全约束（保留；不参与普通历史淘汰）
  > 当前用户问题与本轮任务状态
  > 最近对话及必要工具结果
  > 与当前问题匹配的长期记忆/历史摘要
  > 较早且低相关历史
  > 无关历史与冗余工具输出
```

知识库命中是证据资料而非控制指令；即使它被用于回答，也不能提升为安全/系统约束。`【分析】`“优先级”既包含冲突时的可信来源，也包含预算不足时保留/淘汰次序，两者不能混为一个简单的消息数组顺序。

### 5.2 已实施的首期增量

- **相关召回**：在 `src/chat/storage.ts` 对中文二元字组/英文词项覆盖率、完整短语、字段命中和轻量新鲜度打分；项目范围隔离不变。无相关项时不为了凑数量注入无关记忆。
- **召回预算**：长期记忆上限由 8 收敛为 5，摘要仍最多 5；相关性先排序，调用方再按既有上限截取。
- **压缩保护**：`src/chat/engine.ts` 在有至少三轮对话时保留最近两轮 user 往返；较短对话只保护当前轮，避免两轮内超长历史无法压缩。
- **首轮预算门**：从按消息数量门控改为每轮检查 token 预算；预算内请求不改动，少量但超长的消息现在也能触发既有压缩流程。
- **摘要契约**：压缩与会话摘要提示明确要求保存目标、用户确认事实/约束、决策、完成项、未决问题和下一步，并区分事实与推测、避免复活过期方案。
- **冲突说明**：system prompt 说明安全约束优先，当前问题/任务高于近期对话和旧记忆；知识库继续作为资料而非指令。

没有增加依赖、模型调用、数据库迁移或跨项目记忆范围。代码回归覆盖相关项排序、无关新鲜记忆过滤、近期轮次保护和少消息超预算检查。

### 5.3 逐项差距与取舍

| 维度 | 业界原则 | Omni 首期 | 当前差距/取舍 |
|---|---|---|---|
| 能力 | 当前任务状态与相关历史分层 | system 规则、最近两轮、召回项、旧历史已有边界 | 没新增独立任务状态数据模型，避免大规模改动 |
| 相关性 | 相关度与时效辅助记忆召回 | 本地词项覆盖、短语加权、轻量 freshness | 不具备语义同义词召回；需用样本观察漏召 |
| 质量 | 摘要保存明确事实、决策与待办 | 提示已明确字段与事实/推测边界 | 模型可能不完全遵循提示；待用真实会话评估 |
| 性能 | 预算前置、冗余内容先处理 | 每轮 token 检查，无新增网络调用 | 需要观察每轮估算耗时和少数超长不可压缩请求 |
| 成本 | 避免额外检索/评估模型 | 复用本地数组与现有压缩模型调用 | 超预算摘要调用机制保持原样 |

## 6. 分阶段升级与验证

### Phase 1：低风险确定性改动（已实施）

质量目标是减少无关召回、保住近期任务状态并检查短消息数的大上下文。验证：相关性/范围/保护轮次/预算门单测，TypeScript 检查。当前结果：定向测试 78 项通过，`tsc --noEmit` 通过。该结果证明回归行为符合预期，不代表线上模型回答质量已证明提升。

### Phase 2：真实任务集对照（待观察）

积累并脱敏固定样本，覆盖用户纠正旧偏好、“继续刚才任务”、过期和无关记忆、多工具后超窗、只有少量但超长消息、知识库提示注入。对比约束遵循、任务续接、误用过期记忆、工具轮完整性、token 和额外延迟。未达到“质量不退化且至少一项成本/失败率改善”前，不提高权重、不引入语义模型。

### Phase 3：按证据决定是否扩展

仅当样本确认词项召回漏掉大量语义相关记忆时，才试验本地 embedding/混合召回；若摘要丢失任务事实，再考虑显式 task-state 结构和摘要版本化。保持原会话为可追溯事实来源，并允许重新生成摘要。

风险控制：一元词项/通用词可能产生误召，故使用多词覆盖门槛与小候选上限；新鲜度只作轻微排序信号，不让新近但无关内容通过相关过滤；近期保护区可能提高 token 占用，短对话回退到单轮保护；模型生成摘要不等同于事实校验。

## 附：实施边界

该首期是启发式排序而非语义相关性真值，也不将 system 消息数组顺序视为硬权限系统。项目/会话范围隔离仍由现有 `memoryScope` 逻辑负责。无关记忆默认不为填满条数而注入；若用户当前输入与旧记忆冲突，旧记忆仅作为历史信息。
